# P09. Forgetting: fade, archive, do not delete

**Principle.** Markdown takes very little space, so deleting is not necessary. Knowledge **fades**, it does not vanish; what is finished is **archived**, not deleted.

**Why.** Deleted knowledge does not come back; archived knowledge does. In a learning system, "old" sometimes becomes important again.

**Practice.**
- Learned rules lose weight without use; a dormant rule is no longer loaded but stays (P05).
- What is finished or inactive goes to an `Archive/` folder, with a date and a one-sentence reason.
- **Exception: what is certainly superseded.** Something fully obsolete that has been reliably replaced (for example an old definition of a skill that the new version has proven to replace) may be deleted, if the old text is still reachable in version history.
- Notes or tasks the owner dropped in are never deleted without asking; at most moved.
- The fate of large binary files (media, session transcripts) is decided by the backup principle (P10).

**Check.**
- Is there an `Archive/` folder, and is it used?
- Have agents deleted content without the owner's yes? (Check version history or git log.)

**Adopt.** Create an `Archive/` folder and put the rule in the vault entry file: "archive instead of delete".
