# Flow 5: Advice

After adoption, the repository stays useful as an advisor. The person asks a question; you answer from the principles and the guides, applied to **their** vault.

## Common questions and where the answer lives

| Question | Read |
|---|---|
| How do I connect a new tool (mail, calendar, CRM, task manager)? | [`guides/add-a-connector.md`](../guides/add-a-connector.md), P07, P08 |
| How do I turn something I do repeatedly into a skill? | [`guides/add-a-skill.md`](../guides/add-a-skill.md), P04, P05 |
| How should I work with PAROS day to day? | [`guides/daily-work.md`](../guides/daily-work.md) |
| Do I need a new agent for this? | P03: usually not; check the six reasons for a separate run |
| Where should this piece of information live? | P01, P12, and the vault's own source map |
| Can I delete this? | P09 |
| Is my setup safe if a machine dies? | P10 |
| Something stopped working silently. | P11 |

## How to answer

1. Read the relevant principle and guide.
2. Look at the person's vault: what already exists that the answer should build on.
3. Give a concrete proposal for their vault, with the reason (which principle) in one sentence.
4. If it means changes, offer to do them step by step, with the same safety rules as adoption.
5. If the answer taught you something the repository does not say yet, tell the person; they may want to share it back.
