# Flow 3: Personal guide

Goal: a short, personal course that explains **this person's own vault** through the PAROS principles: what it looks like now, what could change, why, and which principle is behind it. It is written into their vault as `PAROS/GUIDE.md`, in their language, so they can reread it, and so a future agent session can pick it up.

## Input

`PAROS/DIAGNOSIS.md` (run flow 2 first if it does not exist) and the answers the person gave.

## Structure of the guide

1. **Your vault today** (half a page): its shape in plain words, the areas, what already works well. Start with strengths.
2. **The friction you named:** the thing that annoys them most, and which principle addresses it.
3. **One chapter per relevant principle**, ordered by impact for this person (not by number). Each chapter:
   - *What it means*, in two sentences.
   - *How it looks in your vault now*, with a concrete example (a real file or folder).
   - *What would change*, with a concrete example of the result.
   - *Why it is worth it*: the reason behind the principle, tied to their situation.
   - *Effort*: small, medium or large; and whether it can wait.
4. **Your first week:** three to five concrete steps, the core first (entry file, frontmatter, task list, search).
5. **How to keep going:** how to ask the agent for advice later, and how updates of this repository reach them.

## Rules

- Concrete beats general: every chapter points to their own files.
- Short beats complete: a guide that is read is better than one that is thorough. Aim for something readable in fifteen minutes.
- Skip principles marked `not needed`; put `later` ones in a short final section.
- Ask before writing the file. Offer adoption (flow 4) at the end.
